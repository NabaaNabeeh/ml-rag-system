Embeddings and Vector Search

An embedding is a way of representing data, such as words, sentences, or entire documents, as a list of numbers called a vector. These vectors are designed so that items with similar meaning end up close to each other in the vector space, while items with different meanings end up farther apart. This allows a computer to compare the "meaning" of two pieces of text mathematically, rather than just comparing exact words.

Embeddings are typically generated by a trained neural network called an embedding model. For example, the sentences "I love hiking in the mountains" and "I enjoy trekking through hills" would likely produce embedding vectors that are close together, even though they share very few of the same exact words, because their underlying meaning is similar.

Once text has been converted into embeddings, it becomes possible to perform semantic search: instead of matching exact keywords, a system can find the pieces of text whose embeddings are most similar to the embedding of a search query. This is typically measured using a distance metric such as cosine similarity or Euclidean distance.

To make semantic search efficient over large collections of documents, embeddings are usually stored in a specialized vector database, such as FAISS or ChromaDB. These databases are optimized to quickly find the nearest vectors to a given query vector, even when there are millions of stored embeddings, using techniques such as approximate nearest neighbor search.

A typical semantic search pipeline works as follows: documents are split into smaller chunks, each chunk is converted into an embedding vector, and all vectors are stored in a vector database along with their original text. When a user submits a query, the query itself is converted into an embedding using the same model, and the vector database returns the stored chunks whose embeddings are most similar to the query embedding. This approach forms the foundation of many modern retrieval-augmented systems.
